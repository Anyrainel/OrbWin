# LAN UI / authoritative owner contract

2026-10-25. The bounded source IPC operations below are registered; activation
remains unavailable until protected native helper registration is qualified. Root owns the
frontend and thin Rust adapter; the existing Go ServiceRuntime owns native facts,
durable ownership and operation state. Renderer-selected native adapters, SID,
PID, program/helper paths, rule keys, receipts and acknowledgement booleans are
never accepted. Existing internal StartLAN(StageRequest) is NOT a renderer API.

## Input selection

```ts
type LANSelection = {
  containerId: string; startedAt: string;
  hostPort: number; containerPort: number; protocol: "tcp" | "udp";
  interfaceGuid: string; interfaceLuid: string; localAddress: string;
  profile: "private" | "domain"; clientNetworks: string[];
};
```

All fields are untrusted selections. The owner targets only its configured
daemon, verifies exact container incarnation/publication, resolves the current
generation itself, observes actual GUID/LUID/address/profile and canonicalizes
bounded private CIDRs. It derives caller identity, installation, transaction,
nonce, worker asset hash, native binding and StageRequest. A frontend-supplied
generation is unnecessary and must not replace the current source observation.
No engine publication/default/profile is changed by choosing a LAN interface.

## Closed operations in existing local-services request envelope

| operation | Allowed operation-specific fields | Owner result/behavior |
|---|---|---|
| `lan-options` | none | Bounded current published services and native interface/profile choices; read-only, no helper launch/elevation. |
| `lan-review` | `revision`, `lanSelection` | Fresh read-only canonical review; no elevation, staging, worker or rule. |
| `lan-reconcile-review` | `lanReviewId`, `lanReviewSha256` | Atomically revoke an unconsumed retained review, return its original operation mapping if consumed, or unknown. Missing/prior-runtime records never prove absence or revocation. |
| `lan-activate` | `revision`, `lanReviewId`, `lanReviewSha256` | Consume one retained review, return accepted operation immediately; native helper supplies the attended exact-scope confirmation. |
| `lan-cancel` | `lanOperationId` | Cancel that owned setup, close/join any child; distinguish no dispatch from unknown completion. |
| `lan-remove-review` | `lanLeaseSha256` | Inspect retained protected ownership and return exact removal review. Never accept native rule keys from the UI. |
| `lan-remove` | `revision`, `lanReviewId`, `lanReviewSha256` | Consume removal review; close/join LAN ingress before one reviewed rule retirement. Ordinary workload/HTTP access remains independent. |
| `lan-inspect` | `lanLeaseSha256` | Re-read exact protected receipt/provider state without replaying Create/Delete. |
| `lan-settle-helper` | `lanOperationId` | Read-only recheck of a previously acknowledged retained namespace full ID; durable settlement only on same-daemon exact absence. No name adoption/retry Delete/firewall CAS. |

The existing `snapshot` operation returns statuses. Reject all unrelated fields,
unknown fields, duplicates, wrong-case aliases and trailing data in the LAN
request shapes. IDs are fixed opaque canonical lowerhex values generated by
the owner: review/operation IDs 32 characters, review/lease digests 64. The owner
binds each review to runtime instance, settings revision, exact canonical selection
and current generation. Keep at most 16 pending reviews, a 60-second review TTL
and permanent denial-only lease tombstones up to the existing 4096 bound. An
activation consumes its review BEFORE dispatch. Duplicate submissions return
the existing operation reference or a used-review error; never dispatch again.
After expiry/drift request a fresh review. Source/read errors cannot invent a
publication generation or make activation available.

ServiceResponse includes optional `lanOptions`, `lanReview`, and
`lanReconciliation:{reviewId,reviewSha256,outcome:"revoked"|"operation"|"unknown",operationId?}`.
Every consumed review has its own immutable operationId/reviewId pair; removal
uses a new operation and preserves the activation pair. Operation mapping proves
correlation only, never completion or cleanup. Exact field spelling is defined in
`localnet/lan_options.go` and stable for parallel Rust/UI implementation:

```ts
type LANOptions = {
  version: 1; readAt: string; expiresAt: string; complete: boolean;
  sourceAvailable: boolean; sourceUnavailableReason?: string;
  helperAvailable: boolean; helperUnavailableReason?: string;
  publications: Array<{
    containerId: string; containerName: string; startedAt: string;
    hostPort: number; containerPort: number; protocol: "tcp" | "udp";
    available: boolean; availabilityReason?: string;
  }>;
  interfaces: Array<{
    interfaceGuid: string; interfaceLuid: string; alias: string;
    privateAddresses: string[];
    profile: "private" | "domain" | "public" | "unknown";
    available: boolean; availabilityReason?: string;
  }>;
};
```

The owner bounds discovery to 64 running container candidates, 256 publication
choices and the observers' 128 adapters, with one options query in flight and a
five-second combined read budget. The options expiry is at most five seconds
after the oldest included observation. `complete:false` visibly reports partial,
over-budget or failed observations. Names and aliases are display text; never
infer publication identity from HTTP routes/labels, ask users for manual GUIDs,
or treat an options value as native authority on review. Each selected address
must be one of the owner's currently observed preferred private IPv4 addresses
on an operational hardware candidate. Public/unknown/ambiguous profiles remain
visible but unavailable, with a stable reason code. The list is empty when no
eligible published workload exists; no made-up generation/candidate is supplied.

`sourceAvailable` means publication-v2 capability was actually observed for the
queried targets. When there are no running publications it is false with
`no-published-services`; that does not assert an unsupported backend. Unsupported
schema/404 is `publication-v2-unavailable`; failed/incomplete reads are
`publication-source-unconfirmed`. Successful per-target choices may be shown in
a partial list, but stale/incomplete choices are never marked available. Helper
availability is independently reported, so safe options inspection stays useful
before attended administrative setup is enabled. UI must disable activation
unless its fresh review is available and should refresh expired options.

Add optional `lanReview` to ServiceResponse, alongside existing state/error:

```ts
type LANReview = {
  reviewId: string; reviewSha256: string; expiresAt: string;
  selection: LANSelection; publicationGeneration: string;
  purpose: "activate" | "remove";
  available: boolean; reasonCode?: string;
};
```

`available` requires all source/component/helper registration gates. An unavailable
review must supply a stable reason such as `publication-v2-unavailable`,
`helper-unregistered`, `interface-changed`, `public-profile-refused` or
`ownership-unconfirmed`; do not offer activation that can only return a fake ready.
Display the canonical read-only generation as review context, not a user input.

## Owner-derived snapshot statuses

Extend the current minimal `RuntimeSnapshot.lan[]` status with this bounded
public shape; no private provider keys/native file/pipe identity is exposed:

```ts
type LANAccessStatus = {
  operationId: string; leaseSha256?: string; selection: LANSelection;
  sequence: number; updatedAt: string;
  phase: "awaiting-admin" | "awaiting-confirmation" | "staging" |
    "starting" | "ready" | "closing" | "closed" | "cancelled" |
    "cleanup-pending" | "removed" | "failed";
  ingress: "closed" | "ready" | "unknown";
  firewall: "not-dispatched" | "created" | "removed" |
    "create-unknown" | "remove-unknown";
  canCancel: boolean; canInspect: boolean; canReviewRemoval: boolean;
  reasonCode?: string; error?: string;
};
```

Only positive native rule ownership/readback, fresh combined source/interface
evidence, exact child identity and completed worker acknowledgement allow ready.
Stop requests/timeouts are closing/unknown until positive native child/flow join.
Unknown rule cleanup can coexist with known closed ingress because the dedicated
process has exited and its private program path is never reused. Do not present
unknown Create as an owned rule merely because an instance exists. Read-only
receipt recovery may discover an already durably acknowledged positive completion;
it still requires a new removal review and never silently activates ingress.

An updated status sequence orders UI changes. A disconnected/stale snapshot
must show current state as unconfirmed, not keep a green ready indicator beyond
the 5-second observation freshness budget. Native expiry independently closes
active streams. Poll snapshot/inspect after a lost response; do not resend an
uncertain activation/removal. Cancellation before dispatch is cancelled with
firewall not-dispatched; cancellation after dispatch drains/records the actual
outcome and retains unknown ownership. A native exact-scope helper cancel keeps
ingress closed. Removal/cleanup failure never restarts a workload or another engine.

## Nonblocking owner implementation requirement

The ordinary actor reserves/consumes reviews and listener bindings before
dispatch, then owns one bounded setup worker and typed completion events. It
never registers synchronous internal c.start as the public activation handler.
No controller mutex covers attended Stage/Commit work, so committed leases can
refresh while setup awaits consent. Protected review/operation/transaction
mapping must flush before Stage. The complete worker lifetime, including a
stalled protected-store call, is joined before runtime/ledger shutdown. Caller
loss cannot cancel or replay dispatch; an immediate accepted reply is not ready.

Automatic cancellation/drift/shutdown closes and positively joins the exact
child/flows, then releases namespace references. It never launches administrative
retirement. Protected dormant rule/path/tombstones remain independently durable
for explicit reviewed removal. Plain LAN-only generations reuse the same owner
without HTTP names, listener or CA. Enabling HTTP adds its resources to that same
LAN owner/backend. HTTP disable, port/root reconfiguration and failed HTTP setup
retire only the HTTP view; LAN keeps its exact lease identity and independent
refresh. Each HTTP view has a unique owner identity, so late old-view teardown
cannot release a new HTTP view or a LAN reference. Whole runtime shutdown closes
the shared backend only after exact LAN and HTTP joins.

Use the already proposed one-shot helper total 120-second setup budget, at most
60 seconds of native exact-scope review, native calls at most 5 seconds clamped
to remaining time and external 150-second helper process cap. A cap/interruption
cannot promise no late provider commit; retain protected intent. A read-only
review/snapshot RPC remains bounded normally. Source preparation, UI work and
pure tests require no unattended administrator action. Actual provider/consent/
packaged/native acceptance remains a separate root-controlled gate.
