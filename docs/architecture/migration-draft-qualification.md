## Source harness and caller boundaries

`scripts/migration-draft-qualification.mjs` exports `qualifyDraftReopen`. Importing
it does no I/O. Its sequential callbacks are supplied by the reviewed root runner:

- `readSource`: actual native `ReviewDesktopMigration` result, requiring success,
  nonmutation and bounded valid JSON; no substituted source snapshot.
- `inspectConnection`: actual native `wsl_migration_project` for the fixed chosen
  registration/root/signature. It never connects or manufactures `shared_source`.
- `inspectMapping`: actual native `migration_mapping::inspect` with the saved
  Windows path, actual saved SHA, reconstructed narrow semantics and target.
- `validate`: actual compiled production `operations::run` using typed Compose or
  WslCompose Validate, including the WSL mappingReview/reviewedDaemon returned by
  the production frontend precheck. No direct Docker substitution for Validate.
- `changeMapping`/`restoreMapping`: edit only the newly saved nonce mapping.
  Revalidate root/file identity and original/known-changed SHA immediately before
  writing. Refuse another writer's unexpected bytes; retain/audit instead of
  overwriting. Restoration is attempted even if the edit callback fails after an
  uncertain write. Mapping changes are restored before the source-removal phase.
- `removeOwnedSource`: remove only the stopped nonce source container after exact
  ID/name/labels/mount guards. Run this LAST, because a removed container ID cannot
  be recreated. Old saved hints must then fail; do not silently adopt a replacement.
- `verifyBaselines`: enforce the identities, retained workloads/configurations,
  WSL connection record and four original files described above. Fixtures may
  differ only by the recorded expected step. Outer cleanup remains mandatory even
  if this callback or an assertion fails.

`roundTripDraftInputs` uses the actual production remembered-input owner against
an isolated serialized storage value, then installs a fresh read-only storage
object and loads the matching bookmark. The root runner may retain those exact
bytes in its Windows artifact folder. This is restart-style serialization
coverage, not a WebView storage write or an actual app/window restart. The result
always reports `uiRestartQualified:false` and `upQualified:false`.

The new ignored native test
`operations::qualification::migration_draft_qualification::owned_migration_draft_step`
(retrieve the exact compiled name with `--list` before invocation) consumes one
hash-pinned request file from that nonce artifact folder. It requires
`ORBWIN_QUALIFY_OWNED=1`, `ORBWIN_QUALIFY_DRAFT=1`, the exact
`ORBWIN_QUALIFY_DRAFT_NONCE`, `ORBWIN_QUALIFY_DRAFT_REQUEST` and
`ORBWIN_QUALIFY_DRAFT_REQUEST_SHA256`. Requests are bounded to 1 MiB and typed;
responses and native records have unique, never-overwritten sibling filenames.
The test calls the existing Harness/production request path, records the checked
owned target before/after, and admits only Desktop source reads, exact approved
connection inspection, nonce Windows mapping inspection and fixture-only
Validate. It rejects Up, file-copy, lifecycle, container/volume mutations and
unrelated paths. The root runner parses the returned Result and outcome, rather
than treating a test-process exit as proof of a successful product operation.
An expected product refusal is a recorded response, not a harness panic.

## Ordered journeys

1. Root creates/guards the new Windows source project and volumes. Use the native
   UI mapping Save dialog for its new Windows mapping if qualifying the full save
   UI; record actual Rust-returned disk SHA. A harness-created canonical mapping
   can cover subsequent inspection only and must not be called Save-dialog proof.
2. Actual production precheck reads source+target, actual native Validate succeeds,
   then an explicit remember choice is simulated through the production owner.
   Reload serialized inputs under a fresh storage object; source/target/member/
   image/mount identity and actual mapping SHA/semantics are rechecked, then actual
   native Validate succeeds again. No target workload is created.
3. Change only the known saved mapping bytes, retain the old bookmark SHA and
   require refusal. Windows refuses in native inspection before Compose dispatch;
   WSL sends a Validate helper which refuses changed bytes before configuration
   resolution. Require the specific mapping-byte diagnostic; missing plugins,
   disconnected projects and generic transport failures do not pass this case.
   Restore only the exact known edited bytes, then Validate succeeds again.
4. Remove only the verified stopped source fixture container. Fresh source review
   must reject the saved member identity before any native Validate call. Test
   cancellation before reads separately; no callback/Compose dispatch is allowed.
5. Repeat with the WSL child/base and explicitly reviewed root-level mapping,
   using actual WslSaveMapping to obtain guest-byte SHA. Keep source-engine and
   project-distribution identities separate. The guest helper rechecks recorded
   source/shared root and mapping before/after config and before exec.
6. Root cleans exact owned resources/files, verifying no adoption or unknown edits;
   retain evidence and any uncertain object instead of forcing deletion. Remove
   containers by full verified ID without `--volumes`; remove only verified empty
   fixture networks and unadopted labelled volumes. Never remove shared cached
   images. Guest files require the recorded registration/root signature, regular
   non-link type and expected SHA; remove only those exact new paths, then rmdir
   the empty nonce child. Compare all baselines, original four file hashes and
   connection record, and record cleanup errors separately from product results.

The actual UI acceptance is additional: on an isolated development app profile,
record the unchecked remember checkbox, explicit Validate/save, close/reopen the
app, select the named bookmark, verify the displayed provenance and separately
confirmed Validate; verify loading/cancel/error/focus/keyboard behavior. Do not
clear or replace the user's live remembered-input store/profile to automate it.
If isolation or UI access is unavailable, keep this gate open.

Up/data-use is a separately granted lane after these checks. It requires a newly
owned nonempty dataset, owning export/import/restore receipt links, fresh image/
volume/target guards, no port collision, explicit Up confirmation, observed data
read/use/preservation, exact cleanup and all three-engine/global baselines. This
Validate-only harness cannot qualify Up or complete application migration.
