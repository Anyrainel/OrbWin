# Focused implementation review

Self-review on 2026-10-22 Pacific; this is not independent review or phase approval.

## Host/backend boundary

The four source patches change product identity/configuration and paired
networking constants, not Moby or Docker packet content. Host/guest values are
checked together; one product guest is supported. WSL's global distro naming
was audited in the pinned Lima driver. Private client paths are established before
CLI construction because even dynamic help can autostart upstream services.
Foreign instance names are rejected before command execution. Upstream tests and
headers remain; a clean checkout accepts the patch series and source hashes.

Runtime proof verifies build/patch/binary identity, refuses an existing guest
unless an explicit recorded home is selected, checks route overlap, and checks
registration BasePath before any owned stop. No global WSL action, prune, context
switch or competitor stop is present. Restart readiness must include the current
boot's completed upstream Lima condition, not just persisted App readiness or one
early Docker response. Errors and later retry evidence are retained separately.

Buildx needs its own endpoint review: explicit Docker host alone does not constrain
an inherited remote builder. The baseline now selects the default Docker builder,
uses an owned Buildx config and clears `BUILDKIT_HOST`. Workload images are pinned
to observed repository digests. Cleanup is restricted to generated Compose projects,
their test volumes and the exact built test-image tag. Interrupted CLI/harness
cleanup still needs dedicated qualification; no broad reliability claim is made.

## Native adapter

The desktop only reads the fixed pipe. Its local proof record/build tuple and
daemon ID must agree; identity is checked before and after the inventory snapshot.
All four lists must parse as object rows or the snapshot fails. Unknown fields are
preserved as JSON rather than translated or discarded. There is no host shell,
renderer-specified binary/path or arbitrary CLI argument surface. Competing
context/TLS environment selectors are removed and every Docker call has explicit
host/config arguments. Read subprocesses have output caps, deadlines and cleanup;
timeout, overflow, error and decoding tests pass. Window closure has no lifecycle
hook and an actual close/reopen check left the same daemon reachable.

Local development artifacts are trusted inputs, not a signed production discovery
or update mechanism. Named-pipe ACLs, file ACLs, installation trust, support-bundle
redaction and privilege behavior remain security qualification work. Source-build
provenance does not establish absence of vulnerabilities in upstream components.

## Frontend

Backend snapshots are authoritative; no mock data is used in the default app.
Unavailable, failed and truly empty results differ. Duplicate reads are blocked;
inventory failures clear accepted resources rather than fabricate zero counts.
Inputs/controls have names, visible focus styles and current-page semantics.
Rendered native connected/image and browser unavailable states were inspected.
Filter text changed through native automation without a proven React update;
reliable keyboard/filter verification, supported scaling/window sizes, themes,
large lists, streaming and comprehensive accessibility coverage remain open.

The full phase surface is explicitly incomplete. Existing limitations are ledgered,
including native Windows mount syntax and resource allocation scope. No phase,
parity, reliability, performance or clean-room claim is justified by this review.
